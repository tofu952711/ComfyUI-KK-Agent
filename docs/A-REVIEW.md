# A 链路审核与参考视频

不足 32 秒进入 A，32 至 60 秒进入 B。此次更新没有修改分流阈值。

## A 的执行顺序

完整原片抽帧、音轨转写 → 准备最长 30 秒的参考视频 → A 反推草稿 → 独立审核 AI → 最终提示词。

A 的反推和审核继续使用完整原片的抽帧、转写和参考图片，包括超过 30 秒的尾部信息。仅下游 Seedance 使用的参考视频保留前 30 秒；不足 30 秒不裁切、不补长。原始素材不改写。

分流入口的 `video1` 可与独立反推和审核并行送往打码、保存节点；`video2—video5` 不执行。完整视频单节点也执行同样的反推和审核流程。

## 填写规则

- 原来的「系统提示词（原Skill正文）」用于生成 A 草稿。
- 新增的「链路A：审核规定」用于审核 A 草稿，可编辑全文或右键转为输入连接文本节点。
- 「链路B：审核规定」仍仅供 B 使用，两份审核提示词不会串用。
- 「审核AI」配置现在供 A/B 最终审核共用。选择「沿用当前AI」或填写独立审核接口的 Key、地址、模型和协议。

默认审核全文只是文本框默认值。自定义文本会完全替换默认全文，不叠加默认检查项。程序会附带原始用户要求、反推规则、完整素材证据、草稿以及返回审核 JSON 的流程说明。

审核规则不能为空。编辑检查范围时，请保留 JSON 返回契约。A 整篇草稿视作第 1 段。

通过示例：

```json
{"status":"approved","checks":{"自定义检查项":true},"issues":[],"edits":[]}
```

修正示例：

```json
{"status":"corrected","checks":{"自定义检查项":true},"issues":[],"edits":[{"segment_index":1,"old":"草稿里精确且唯一的原文","new":"修正后文字","reason":"修改依据"}]}
```

审核仍校验段号、引用唯一匹配、修改重叠和空正文，允许 `old == new`。明确拒绝或无效审核响应不会当作最终成品交付；草稿、审核响应和错误保存在插件数据目录 `a-results/<run_id>/`。分析证据包含阶段用量、审核耗时、模型及记录位置。

每次审核使用独立的任务会话。节点追加新字段，旧字段顺序保持；旧工作流未保存 A 审核字段时使用默认全文，明确清空会提示填写。更新后请重启 ComfyUI、刷新网页，并检查新增输入框。

## 取消与并发

视频预处理放在独立的子进程中，解码限制线程数。取消任务时，取消标记保留到本次任务结束，停止本任务的预处理、模型请求及审核；取消进度显示为「已取消」。同步打码节点占用 ComfyUI 执行循环时，反推任务仍会提交到工作线程。
