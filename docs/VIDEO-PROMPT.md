> **当前执行策略：31.9秒及以下直接反推；超过31.9秒且不超过60秒先裁成两段，再反推。** 第一个文本框为用户要求，第二个为反推系统提示词，新增第三个「详细分段要求（31.9＜时长≤60秒）」。无论第三框是否填写，均由AI结合剧情、分镜、前两框改编目标及参考图判断切点，最多两段；脚本只执行实际裁切。先完成实际裁切，再启动第二框反推。短视频不读取、不发送第三框；超过60秒明确报错。现有五个VIDEO端口保留兼容，仅分段时使用前两个；不分段时五个VIDEO接口全部阻止下游保存。下方旧并行／五段策略已被此策略替代。

> **当前接口：image1—image10 + video1—video5。** 图片均为可选的通用参考，含义由用户要求／系统提示词说明；未连接的编号不重排。保留原来的提示词、分析证据、状态三个输出，在后面增加五个VIDEO输出。超过31.9秒且不超过60秒时，AI需通过set_video_segments提交两段连续覆盖全片的秒数，节点才会实际裁切；31.9秒及以下没有VIDEO输出，不保存整片。分段视频包含原音轨，采用CPU H.264/AAC编码；输出存于VIDEO内存对象，任务临时目录清理后仍有效，需要长期保存请接SaveVideo。旧人物／商品连线迁移到image1／image2，文本控件顺序不变。

> **节点精简：仅保留「DSH Agent 完整视频反推」。** 已删除提示词引擎、帧阵列拼图、视频反推（独立 Key）的节点实现与注册，并移除对应旧示例。现有工作流请使用 full_video_workflow.json 或 full_video_api.json；本地与云端入口均只提供完整视频节点。下方历史文档提到的旧节点已不再提供。

> **当前行为：两个文本框。** 完整视频节点第一个框「本次用户要求」发送为用户输入，第二个框「系统提示词（原Skill正文）」发送为模型系统提示词；第二个框默认为空，可直接粘贴规则，也可右键转为输入连接文本节点。插件不再内置或加载爆款裂变 Skill。旧工作流若仅显示一个框，请重新添加完整视频节点。原有视频预处理、CPU声音工具、重试及任务清理保留。下方旧版本中的内置爆款裂变说明已不适用。

# 完整视频反推专用路径（0.8.4）

导入 `examples/full_video_workflow.json`，把 ComfyUI 原生 `LoadVideo` 接到「DSH Agent 完整视频反推」的原视频，两个 `LoadImage` 分别接人物图1和商品图2。提示词输出接下游文本输入。每位使用者在节点填写自己的 API Key，不需要面板。

示例使用当前测试路线：`https://api.zdjapi.com/v1`、`gpt-6.1-sol`、`openai-completions`，Key 留空。可换为其他同时支持图片和工具调用的 OpenAI 兼容端点。DeepSeek 官方路线使用 `https://api.deepseek.com/anthropic`、`deepseek-flash`、`deepseek-messages`，填写官方 Key。不同服务的 Key 不能混用。

本版继续通过本地官方 DeepSeek Harness SDK 运行 agent。没有把模型改成一次直接调用，也技能仅按用户明确要求删除“不编造材质或功效”一句，其他内容保持原样。

## 执行流程

1. 在独立临时目录保存本次视频，读取元数据。
2. 解码器直接缩小原始帧，检测相邻帧变化作为切镜候选。
3. 一次批量解码取出全片概览、每秒4帧的密集动作序列、候选切点四帧对照，以及密集采样仍遗漏的短镜头候选中点。≤60秒视频密集采样间隔0.25秒，长视频降低密度至约240个位置，并记录实际覆盖；概览约每秒一帧、最多约60个位置。切点对照取前约2帧、前1帧、切点帧、后约3帧，每行一个候选，用原视频PTS标注；最多预览48个变化较强的切点和48个短区间，不将候选自动认定为真实镜头。整片取证接近下午Codex的密集采样与切点多帧复核，不复制当时的环境探查和失败修复过程。
4. 有本地 SenseVoice 模型时，转写全文和约5–10秒窗口，保留 token 与估计起始时间。自动转写不等于真实声线、音乐分析，也不是对白强制对齐。没有模型或音轨时明确记录状态，不自动下载模型。
5. 对16kHz单声道音轨计算自相关音高及宽频带谱包络，提供逐秒概况与最多8个声音变化候选。最强的3个疑点额外各取12张真实帧，约每秒8帧，供模型对照口型、人物回应与前后台词。候选数量不等于人数，也不自动判断性别或声纹身份。
6. 用 Harness 自带 `/viral-variation` 直接加载技能，在第一轮模型请求之前提供完整原版正文。人物、商品、视频拼图分别作为图片传入。
7. DSH 理解画面、按原技能换人换品并写提示词；有疑问仍可调用视频工具查看其他时间。新增 `analyze_voices(start,end)` 可按原视频秒数复核最多30秒音轨，并在本地ASR可用时重新转写该段。单帧补看提供长边720像素，批量图按时间排列。不会插帧或生成视频帧。

专用路径只加载爆款裂变技能，关闭通用文件搜索、文件读写、目录切换等工具。保留视频信息、切点检测、取帧、转写、声音复核、技能工具；SDK MCP 客户端还会注册资源工具。没有强制工具调用次数或新的创作检查规则。旧节点保持原有兼容路径。

同一任务内复用切点、转写和已取帧，新时间按关键帧 seek 后解码，不再每次从头扫整段视频。各任务的 Key、会话和素材仍隔离；结束后清理临时目录，不建立跨用户素材缓存。

密集动作图每张最多20帧、5列4行；切点图每张最多4个候选、4列4行。每格视频长边356像素，避免把几百帧塞入一张超大图后失去细节。模型仍可请求长边720像素的单帧细节；远端接口是否另行缩放需以其实际行为为准。脚本只提供观察材料，不自动宣称识别了动作语义、摄影机运动、声音角色或配乐，也不修改原Skill或强制模型只能调用固定轮数。

## 声音补正的边界

这一路径参考 Codex 实测中的音高探查、前后画面复核方式：先发现疑点，再由 agent 结合台词和口型判读；没有直接接入 Codex 内部能力，也没有向当前图片模型传入原始音频。音高估计存在倍频/半频误差，配乐、语调及变声也可能触发候选。预处理本身不使用声纹模型；需要估计人数时，agent 可调用新增的 `diarize_speakers`，获取声纹聚类与每人时间段，CPU按需加载，部署见 [说话人分析](SPEAKER-ANALYSIS.md)。模型估计也不保证准确人数；画外音表示声音与画面的关系，同一人也可在产品特写时继续画外说话。证据不足时须保留不确定性，避免输出未经核实的单一声线结论。

`voice_evidence.json` 保存声学概况、候选、ASR上下文和限制，`preparation.json` 同步记录。覆盖字段中的 `unique_requested_frames` / `unique_actual_frames` 只统计原有概览、密集动作和切点取证；新增声音复核位置单列在 `voice_review_requested_frames`，可与原位置重合。轻量声音分析只依赖已有 numpy；新增声纹工具的权重由部署阶段预置，结果另存 `speaker_evidence.json`，任务运行时不下载。

## 图片完整性（0.8.4）

DeepSeek Messages 在 Files 上传失败时回退为 Base64。完整视频节点把该回退图片总预算显式设为128 MiB，替代默认20 MiB；原始文件上传预算仍为128 MiB。预算针对编码后的图片，不能按磁盘JPEG大小估算：本次同素材20张图片在请求中约27.3 MiB，旧预算会触发省略。

专用 profile 关闭 Harness 的 `image-offload` 自动省略组件；超出预算则报告错误，不在缺失人物或商品参考图的情况下继续生成。其他旧节点配置不变。128 MiB 是本地上限，不代表远端接口承诺接受同样大小；服务端拒绝会显示错误。

真实包内 Harness + 本地拒绝Files的模拟接口验证：同素材20张图全部保留，未出现image/offload或图片省略标记。另有独立合成大图回归验证，不依赖个人素材。这里验证的是传图完整性，没有因而宣称真实官方输出质量已改善；此前真实官方一轮没有保存足够信息，不能倒推它一定丢图。

## 部署

RunningHub 源码包由平台安装 `requirements.txt`，包括官方 SDK/runtime 和无固定版本的 CPU `sherpa-onnx`。其余依赖 `av`、Pillow、numpy、torch 由近期 ComfyUI 提供。需要可启动本地子进程，不需要 Harness 桌面版、系统 Node 或额外网页服务。

0.8.5 的 Windows 便携包及云端源码包已内置 SenseVoiceSmall INT8，文件、词表、来源及许可证位于插件自身 `models/sensevoice/`。节点「本地SenseVoice模型目录」留空即使用包内模型，不查找用户主目录缓存，不在运行时下载；移动或重命名插件目录后仍自动定位。可选填写相对于插件目录的路径或绝对路径，也可设置 `DSH_BRIDGE_ASR_MODEL_DIR` 覆盖。Windows 媒体工具使用 ComfyUI 的 Python，需由宿主安装 requirements.txt 中的 sherpa-onnx；包内 Harness Python 不替代宿主的 ASR 依赖。

公开模板的 Key 留空。用户填入节点的 Key 仍可能随工作流/平台任务输入保存，遵循平台自己的密钥管理方式。

## 模型请求自动重试

连接错误、单次请求超时、限流及服务端临时错误会在同一模型步骤内最多自动重试3次，依次等待5秒、15秒、30秒；保留已完成的工具结果，不重跑整段视频。鉴权、参数、额度或上下文错误不重试。停止或任务总超时会中止等待。 每个失败请求最多执行4次（首次加3次重试），日志显示重试次数、等待秒数和错误分类，最终失败保留底层错误信息。
