# 按时长分段与三个文本框

插件只注册DSH Agent完整视频反推节点。image1—image10保持十个通用可选图片输入；前三个STRING输出及video1—video5的序号不变。

## 固定流程

- 原视频31.9秒及以下（含31.9秒）：不分段，直接按第二个文本框反推；五个VIDEO分支全部阻止执行，不生成视频输出、不复制整片给保存节点，也不保存视频预览。分析过程的原视频临时副本仍在任务结束后清理。
- 原视频超过31.9秒且不超过60秒（60秒包含）：必须先裁成两段，再开始反推。video1、video2返回两段，其余三个VIDEO分支阻止执行。
- 超过60秒：明确提示当前策略不支持；不发起模型请求。

判断依据是实际原视频时长，不将31.9秒附近的数值先四舍五入。分段连续覆盖全片，切点受原视频帧边界约束，不插帧、不变速。

## 三个文本框

1. 本次用户要求：本次人物、商品、参考图职责和反推目标。
2. 系统提示词（原Skill正文）：只控制反推阶段，规则作为系统角色发送；插件没有内置爆款裂变。
3. 详细分段要求（31.9＜时长≤60秒）：无论留空还是填写，均通过独立AI分段会话读取视频证据，结合剧情、分镜及改编目标决定一个切点并提交两段方案。填写时同时遵循本框详细要求。脚本不再等分或自行选择切点。无论填写什么，都不能突破两段上限。

短视频不验证、读取、发送第三框，也不会额外调用分段模型。第三框转为连接输入后采用ComfyUI惰性输入，仅当视频满足超过31.9秒且不超过60秒条件才请求该连接的值。分段模型同时读取第一框用户要求、第二框反推规则及参考图，用于理解改剧情、换品和分镜约束；本阶段不生成最终反推正文。第三框不直接发送给反推模型，AI选定的时间范围及剧情／分镜承接说明会传给反推阶段。

例：32秒视频由AI按内容决定切点，可能是12.3秒，也可能是其他自然剧情位置，不能假定为16秒。第三框可以写「优先对白停顿附近的自然镜头切点，尽量保持两段时长接近」。所有需要分段的视频均由AI判断剧情和分镜切点，CPU只按AI时间范围编码；分段模型会额外产生接口请求。模型漏提交时可在同一分段会话补执行一次，仍失败则报错，不启动反推任务。

## 执行顺序与预览

本地预处理视频／音轨 → 判断时长策略 → （仅超过31.9秒且不超过60秒：AI结合剧情与分镜读取第三框并判断切点 → 裁切两段 → 显示分段预览）→ 按第二框独立反推 → 节点统一返回所有输出。

反推阶段不注册set_video_segments工具，不能再次修改已经完成的分段。反推模型收到真实分段与原视频秒数的对应关系及原片证据，按第二框和本次用户要求交付提示词。需要每段单独的提示词时可在第二框说明输出结构。

保留音轨开关默认开启，关闭时从分段输出移除音轨，分析仍读取原音频。分段用CPU H.264/AAC编码；短视频没有VIDEO输出。分段VIDEO对象存于独立内存，任务目录清理后仍能连接SaveVideo保存。

提前预览在ComfyUI临时目录生成dsh-preview-*缓存。同一客户端同一节点再次运行时清理上次缓存，下次任务也回收超过6小时或数量上限的旧缓存，活动目录保留；系统正在读取而暂时删不掉的文件会在后续任务再次回收。预览不写入永久output目录。

## 耗时与兼容

分析证据包含duration_policy.json、video_outputs、output_compliance、segment_agent_tool_calls、segment_usage及segment_corrections。timings分别记录preparation_seconds、segment_planning_seconds、video_encoding_seconds、agent_seconds和total_seconds；output_review_seconds是agent_seconds内的复核时间，不重复相加。带固定交付模板或内部检查的外接规则在原会话增加一次模型内容复核，最终章节、顺序等格式检查失败则报错，详见EXTERNAL-RULES.md。当前顺序执行，video_agent_overlap_seconds固定为0。分段规划、反推与复核共用timeout_s的模型等待预算，CPU预处理／裁切另计。

新文本框追加在原控件之后，保留已有API Key、接口协议、系统提示词、音轨开关的保存位置；旧API工作流不填写segment_rules_text即可采用默认策略。保留五个VIDEO端口以兼容旧连线，但本策略最多实际输出两段。旧并行裁切、从前两框识别任意分段数量的行为已不再用于节点执行。
